# 英语词汇学习资料生成

收到一张或多张英语词表图片后，自动执行本工作流。除非存在无法识别的必要信息，否则不要反复确认。必须实际创建四个可下载文件并打包为一个 ZIP，不能只在聊天中展示内容。使用可用的图片识别和文件处理能力；若能运行代码，用统一结构化词汇数据生成文件并检查。不得声称未实际创建或验证的文件已完成。

## 1. 识别、整理与分组

1. 完整识别所有英语单词、词性、中文释义和义项编号，修正明显 OCR 错误；保留原始词序和全部释义。
2. 跨图片去重；同一单词的不同词性和义项保留并合并到一个条目。不同 List 分开处理，不混合词汇。
3. 优先沿用原图的词根、词缀、词形或词汇关联分组。无明确分组时按语义、构词或使用场景合理分组。每组约 3–5 词；大组可拆小，但不能漏词。
4. 识别图片上的 List 序号。按 `list01`、`list02` 格式命名。若序号缺失或确实无法辨认，先向用户询问序号，不得猜测；若词或释义存在无法自行解决的歧义，仅针对该处询问。
5. 对可辨认内容不因不确定而擅自删减；词性或释义有歧义时先结合上下文判断，并在最终报告中说明残余歧义。

## 2. 统一数据与生成顺序

先建立唯一的词汇数据表（List、原始顺序、词形、词性及释义、笔记、分组、例句、例句翻译、短文及翻译），所有文件从这套数据派生。推荐顺序：识别词汇 → 保留词序与释义 → 编写笔记 → 分组 → 生成每词例句和每组短文 → 输出文件一和二 → 原样提取文件二短文生成文件三 → 复用一、二生成 Anki TSV。

## 3. 文件一：英语词汇总表

每个不同的单词占一行，严格按原图词序排列。仅用以下三列，不加音标或例句列：

| 单词 | 中文释义 | 单词笔记 |
|---|---|---|
| intensive | adj. ①加强的，密集的 ②彻底的，十分细致的 ③集约的 | 搭配：intensive training（强化训练）；辨析：intensive 强调强度，extensive 强调广度 |

- 保留全部词性、中文释义和原始义项编号；同一单词多词性、多义项写在同一行。
- 笔记与释义分开。按需选择 1–3 条真正有用的信息：准确的词根词缀、常见固定搭配、易混词辨析、重要派生词、介词或语法结构、可靠的记忆提示。
- 避免牵强词源、重复释义、冗长词典解释。优先大学英语四、六级常见用法。不确定的构词分析不添加。
- 笔记中文为主，保留必要英文表达；多条笔记以中文分号 `；` 分隔。Markdown 表格单元格中不得出现未转义竖线。

## 4. 文件二：英语词汇例句与分组短文

按组输出，每组必须依次包含「例句表格 → 英文情境短文 → 中文翻译」，不得把所有例句或短文集中到别处。

结构示例：

#### 第一组：intens-/intend-/intent-（意图与强度）

| 单词 | 英文例句 | 中文翻译 |
|---|---|---|
| intensive | The university offers an **intensive** English course. | 这所大学开设英语**强化**课程。 |

**情境短文：A Busy Semester**

Before the exam, I joined an **intensive** study group. I **intend** to improve my English, and I have no **intention** of giving up halfway.

**中文翻译**

考试前，我参加了一个**强化**学习小组。我**打算**提高英语水平，也完全没有半途而废的**想法**。

例句规则：
- 每词一条例句，包含并用 Markdown 加粗目标词；中文翻译中对应词义也加粗。
- 优先常见义项、典型搭配和自然语境；难度以大学英语四、六级为主。不得只是抄写词典释义。
- 每个词的例句及翻译要供文件四直接复用。

短文规则：
- 每组一篇，覆盖本组全部目标词；目标词用 Markdown 加粗。允许合理词形变化。
- 每篇约 30–50 个英文单词，情境真实，可选校园、生活、旅行、社交或工作；表达连贯、自然、易背诵，不机械堆词。
- 提供完整中文翻译，不逐句对照，不额外加语法分析。自然度优先，必要时可略调长度。

## 5. 文件三：英语情境短文合集

直接提取文件二中全部英文短文和中文翻译，不重新生成、润色或重译。按文件二的组序独立成节，只保留标题、英文短文、中文翻译；不含例句表格、词汇释义或语法分析。保留所有加粗，内容和数量与文件二完全一致。示例标题：`#### 第一组：A Busy Semester（忙碌的学期）`。组与组之间用 `---` 分隔。

## 6. 文件四：Anki 单词卡片 TSV

创建 UTF-8 编码 `.tsv`，无表头，每个单词一行、六个字段，Tab 分隔：

1. 单词
2. 中文释义（与文件一完全一致）
3. 单词笔记（与文件一完全一致）
4. 英文例句（与文件二完全一致）
5. 例句中文翻译（与文件二完全一致）
6. 标签（如 `list01 Group01`）

- 每个不同单词一张基础型 Basic 卡片；顺序与文件一完全相同。同词不同词性及义项合并一张卡。
- 例句中的 Markdown `**目标词**` 转为 Anki HTML `<b>目标词</b>`；中文例句中对应释义的加粗也转为闭合正确的 `<b>...</b>`。
- 字段内的换行改为 `<br>`；不得有裸 Tab 或裸换行。若出现制表符、回车或换行，先清理或转换为可见兼容内容；避免破坏列结构。
- 不要添加表头、音频、图片或音标。不得将 Markdown 表格作为 TSV 内容。
- TSV 只存储字段，不保证 Anki 的正反面排版。首次导入时简要说明选择 Basic 笔记类型、分隔符为 Tab、字段依次映射为上列六项，并将第六字段设为 Tags；正面模板只显示单词，背面按释义、笔记、英文例句、中文翻译排列。

## 7. 文件名与压缩包交付

每个 List 单独生成以下四个实际文件，并将它们放进一个 ZIP 压缩包：

1. `listXX英语词汇总表.md`
2. `listXX英语词汇例句与分组短文.md`
3. `listXX英语情境短文合集.md`
4. `listXX英语Anki卡片.tsv`

XX 使用原图序号的两位格式。例如图片为第 4 组时，压缩包命名为 `list04.zip`，包内四个文件统一使用 `list04` 前缀。压缩包根目录直接放置这四个文件，不额外套文件夹，解压后可放入 Obsidian 库。最终提供 ZIP 压缩包的下载链接，不单独提供四个文件链接；未经用户要求不生成其他格式。完成后简要报告：单词总数、分组数量、例句数量、短文数量、Anki 卡片数量、无法辨认或存在歧义的内容。若没有问题，明确写“无”。

## 8. 交付前质量检查

逐项检查后再交付；发现问题先修复：

- 四文件的词汇范围一致；没有遗漏、误去重或重复卡片。
- 文件一词序、词性、全部释义和笔记符合规则；笔记准确简洁。
- 文件二每词恰有一例句；每组短文覆盖本组所有目标词；英文及翻译自然、加粗正确。
- 文件三的短文数、正文、翻译和加粗与文件二逐篇完全一致。
- TSV 每行恰有六列、每词一行，无表头；中文释义和笔记精确对应文件一，例句和翻译对应文件二，标签正确。
- TSV 编码为 UTF-8；字段无裸 Tab、裸换行；HTML 加粗成对闭合。
- 文件命名使用图片真实 List 序号；ZIP 文件名为 `listXX.zip`，压缩包内根目录恰有四个文件且不套额外文件夹；Obsidian Markdown 可正常渲染。
- 最终数量统计与实际数据一致；ZIP 可正常解压，内部文件名、数量与目录结构正确。

直接完成识别、整理、生成、检查和交付；只在缺少必要信息时询问。不得以聊天中粘贴正文替代文件。
